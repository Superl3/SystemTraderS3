SystemTraderS3 사용법과 한계

SystemTraderS3는 수익을 찾아주는 자동매매 봇이 아니라, 파일 기반 데이터로 전략 실행을 재현하고, 산출물을 검증하며, 손익과 factor exposure를 설명 가능한 형태로 분해하는 로컬 시뮬레이션 골격입니다.

무엇을 하나

입력 데이터 감사, 시뮬레이션, artifact export, replay validation, metrics, factor report, factor attribution, gated risk model, loss classification을 수행합니다.

무엇을 하지 않나

실거래, 브로커 API, 수익 예측, 최적화, ML prediction, 레버리지 자동화는 하지 않습니다.

핵심 철학

없는 데이터를 그럴듯하게 만들지 않습니다. 부족하면 INCONCLUSIVE, 깨지면 FAIL로 보고합니다.

전체 흐름

가장 안전한 사용 흐름은 입력을 먼저 감사하고, 시뮬레이션을 export한 뒤, export된 artifact만 다시 검증하고 분석하는 것입니다.

input_audit simulate validate_run metrics factor_report factor_attribution factor_risk_model loss_classification

중요한 안전선

이 프로그램의 결과는 투자 판단이나 수익 가능성 보장이 아닙니다. 현재 데이터와 규칙으로 run이 어떻게 움직였는지 설명하는 로컬 분석 결과입니다.

데이터 객체

market_prices.csv 또는 *_prices.csv가 필수입니다. benchmark_prices.csv, factors.csv, dataset_manifest.json은 선택입니다.

전략 객체

configs/strategies/*.json에 전략 설정을 둘 수 있습니다. 현재 catalog는 코드가 source-of-truth입니다.

run 객체

export된 run directory는 재현 가능한 artifact 묶음입니다. validation과 분석 계층은 이 디렉터리를 읽습니다.

가장 짧은 안전 실행

처음 확인할 때는 테스트 fixture로 run을 만들고 모든 분석 리포트를 순서대로 생성하세요.

PowerShell quickstart 
rtk python -m unittest discover -s tests

$run = "$env:TEMP\systemtraders3-docs-smoke"
rtk python -m system_trading_s3.input_audit tests/fixtures/valid_multisymbol
rtk python -m system_trading_s3.simulate tests/fixtures/valid_multisymbol --config tests/fixtures/sample_config.json --export-dir $run --run-id docs-smoke --overwrite
rtk python -m system_trading_s3.validate_run $run
rtk python -m system_trading_s3.metrics $run
rtk python -m system_trading_s3.factor_report $run
rtk python -m system_trading_s3.factor_attribution $run
rtk python -m system_trading_s3.factor_risk_model $run
rtk python -m system_trading_s3.loss_classification $run

로컬 대시보드 사용

대시보드는 기존 run을 보고, fixture/drop-in dataset과 config를 골라 새 simulated run을 만들 수 있는 로컬 UI입니다.

서버는 Python stdlib 기반이지만, 브라우저 UI는 Chart.js, Lucide, font를 CDN에서 불러옵니다.

overwrite 주의

기존 run artifact directory는 기본적으로 덮어쓰지 않습니다. 같은 run id를 다시 쓰려면 UI에서 overwrite를 명시해야 합니다.

대시보드 실행 
rtk python dashboard/server.py

# 브라우저에서 열기
# http://localhost:8000

왼쪽 run 목록

runs/ 아래 run directory를 읽습니다. audit status, strategy, return을 빠르게 봅니다.

새 run 만들기

dataset, config, strategy preset, parameter를 선택하고 run id를 지정합니다. inline JSON 편집도 가능합니다.

상세 화면

equity/drawdown chart, trades, audit gaps, factor risk model status를 확인합니다.

rtk가 없다면

이 저장소의 문서는 rtk python 형식을 사용합니다. 환경에 따라 같은 명령을 python으로 바꿔 실행할 수 있습니다.

산출물 파일 해석

아래 파일을 선택하면 역할과 주의점을 볼 수 있습니다. 생성되지 않는 선택 파일은 실패가 아니라 gap일 수 있습니다.

파일을 선택하세요

run directory 안의 artifact를 누르면 설명이 표시됩니다.

PASS

필수 파일과 필드가 유효하고, 해당 계층에서 필수 조건이 충족된 상태입니다.

계속 진행 가능

INCONCLUSIVE

필수 구조는 대체로 유효하지만 benchmark, factor, cost, 표본 수 같은 선택 또는 분석 조건이 부족한 상태입니다.

가짜 숫자 대신 보류

FAIL

필수 파일, header, timestamp 순서, 숫자, enum, accounting replay 등에서 오류가 난 상태입니다.

먼저 수정 필요

risk model 상태 선택기

현재 demo run처럼 factor가 하나뿐이고 관측치가 적으면 risk model은 정상적으로 INCONCLUSIVE를 냅니다.

이 프로그램의 가장 중요한 한계

SystemTraderS3는 simulated-only입니다. 어떤 전략도 수익성 있다고 주장하지 않으며, 실제 주문을 넣거나 broker/exchange와 연결하지 않습니다.

실거래 관련 한계

live trading, broker API, exchange API, real order placement, leverage automation은 없습니다. 대시보드에서 실행하는 것도 로컬 시뮬레이션입니다.

데이터 관련 한계

datasets/us_tech_100_simulated는 synthetic fixture data입니다. Yahoo downloader는 optional dependency인 yfinance, pandas와 네트워크가 필요합니다.

전략과 체결 관련 한계

현재 전략은 등록된 preset catalog에 한정됩니다. execution은 deterministic fill, capped partial fill, carry-forward residual 정도이며 exchange queue, time priority, 실제 유동성은 모델링하지 않습니다.

metrics와 attribution 한계

per-symbol metrics는 trade-realization summary입니다. portfolio equity attribution은 여전히 portfolio-level입니다. factor attribution은 deterministic proxy와 PnL reconciliation이지 수익 예측이 아닙니다.

통계 factor risk model 한계

factor_risk_model.json은 적어도 두 개 factor와 충분한 complete observations, 식별 가능한 OLS design matrix가 있을 때만 계수를 냅니다. 부족하면 INCONCLUSIVE가 올바른 결과입니다.

대시보드 한계

대시보드는 로컬 실험용 UI입니다. production dashboard가 아니며 CDN asset 의존성이 있습니다.

상황별 판단 레시피

문제가 생겼을 때는 결과 숫자보다 artifact와 status를 먼저 보세요.

상황 먼저 볼 것 해석
run이 이상하게 좋아 보임 run_manifest.json, metrics.json, sample-size gap 수익성 판단 전에 데이터가 synthetic인지, row 수가 너무 적은지, benchmark가 있는지 확인합니다.
INCONCLUSIVE가 나옴 gaps 목록 대부분 선택 데이터 부족입니다. 실패가 아니라 "이 분석은 여기서 멈춰야 한다"는 신호입니다.
factor model 계수가 없음 factor_risk_model.json factor 수, 관측치 수, complete row, singular matrix 조건을 확인합니다. 얇은 데이터에서 계수를 만들면 안 됩니다.
체결이 예상과 다름 orders.csv, order_events.csv, fills.csv, risk_events.csv partial fill, residual carry-forward, risk rejection, cooldown 여부를 순서대로 봅니다.
전략 설정이 적용되지 않은 것 같음 run_manifest.json, config JSON, dashboard strategy form 등록된 strategy name과 parameter만 유효합니다. 알 수 없는 key는 작동한 척하지 않고 거부됩니다.
